# NanoJev: source-generated mathematical game library + smoke v1

This patch contains **source files only**, rooted at `main_computer_test/`. It does **not** include a generated `.sqlite3`, `.pt`, or checkpoint and never changes the active trainer.

## Run from `C:\Users\subsi\main_computer`

```powershell
$py = 'C:\Users\subsi\NanoJev\.venv\Scripts\python.exe'

# Disposable full-size end-to-end build: generate everything and destroy copies.
& $py -m tools.nanojev_game_math_smoke --generate --verify-all --report --temporary

# Persist results in a dedicated new directory; fails if it already exists.
& $py -m tools.nanojev_game_math_smoke --generate --verify-all --report

# Opt-in replacement only if the destination was generated by this exact smoke
# and none of its outputs have been modified since the prior manifest.
& $py -m tools.nanojev_game_math_smoke --generate --verify-all --report --replace

# Regression suite
& $py -m unittest tests.test_nanojev_game_transformation_library tests.test_nanojev_game_math_smoke -v
```

Default persistent output: `runtime/game-math-source-smoke-v1/`. All files are constructed from the Python sources on each run. Smoke files are generated in a staging directory and moved into place only after success; all output files are SHA-256 hashed in a manifest.

## Source ownership

- `tools/nanojev_game_transformation_library.py`: **unchanged** established MC3 game catalog, mathematical transformations and verified oracles (229 games, 25 transformation definitions, 2,096 cases at full size, 73 dictionary terms).
- `tools/nanojev_game_math_registry.py`: 58 mathematically defined new or aliased operations; 42 execute with a checked reference function, 16 remain catalog-only. Includes all 14 original numerical execution programs as aliases to exact rational implementations. `MIDPOINT` and `AVERAGE` are aliases; no need to add a new trained OP merely for midpoint.
- `tools/nanojev_game_math_smoke.py`: builds the old 229-game MC3 SQLite database then extends that **same database** with the math registry, dependencies, oracle vectors, game/operator requirements, execution graphs, freeze traces, and T00-T08 presentations. Adds two source-owned example games (auction + provisional betrayal rubric) for 231 total.
- `tools/nanojev_game_library_v1.py`: preserved original captain source, **not imported as an oracle**. Its six literal groups of source definitions are extracted by AST into the database without executing imports or generating misleading gold tasks. Hawk-Dove and Chicken row-payoff dominance conflicts are explicitly detected and quarantined; the v1 fixed-subtraction target is also flagged.

The original captain jackets and scenario external modules were not present in the base snapshot. This package does not claim to reconstruct those missing modules or turn that captain library into a fully integrated trainable source. The 110 safely extractable *source records* are retained for future reconciliation.

## Smoke-gate obligations

1. All mathematical definitions (executable and catalog-only) exist in source and SQLite, have distinct IDs, typed inputs/outputs, mathematical formulas, assumptions, provenance and operator dependencies.
2. No unregistered or cyclic dependency; an executable operator cannot depend on a catalog-only operator. All 42 executable registry entries have explicit, independently authored oracle test vectors. There are domain-rejection tests as well.
3. All 19 legacy scalar formulas and 25 legacy transformations are registered in the same math definition inventory; original transformation oracles are re-run on all 2,096 existing cases. The full inventory is 102 mathematical definitions, besides the existing 73 semantic dictionary terms.
4. The original 14 integer numeric programs are separately mapped to precision-preserving exact arithmetic; existing model weights are not edited.
5. Three frozen graphs — Hawk-Dove, synthetic Betrayal-Loyalty, and first-price competitive bidding — produce nine presentation tiers each, sharing the same canonical `(X,Y,OP,Z)` result. Each stored execution node is replayed, numerical values are exact fractions, and T08 contains only the two defined situation numbers.
6. Example auction answer `Z=81.25` is **only** valid under the frozen synthetic uniform-budget/intelligence/opponent-need model and the verified `rival_high>=own_value>rival_low` condition. General auction optimization remains catalog-only. This is NOT an empirical opponent forecast nor a general auction-theory equilibrium.
7. Existing captain-v1 mathematical claims that contradict its payoff rows are retained for inspection but blocked from supervised gold. Generated outputs distinguish `verified_under_frozen_synthetic_behavioral_model` from `provisional_synthetic_teacher`.
8. Catalog-only games (196 of the original 229) remain visible as a research backlog. Candidate missing-function links are **suggestions**, not verified dependencies. The smoke reports no neural-head results; model learning must be measured separately.
9. Results are reproducibly sourced and cannot replace active training databases. Existing output directories are refused unless `--replace` is explicitly requested; altered or foreign outputs are never overwritten.

```sql
SELECT operator_id,formula,status,inputs_json,output_type
FROM math_operators ORDER BY operator_id;

SELECT program,operator_id FROM math_numeric_program_aliases ORDER BY program;

SELECT game_id,requirement,status FROM math_growth_requirements ORDER BY game_id,requirement;

```

## Boundaries / deliberate non-goals

- No new neural head is implemented, initialized, enlarged, or trained. A database operator does **not** automatically become a model capability.
- No auto-promoting T00-T08 staging rows into `mix_v4`; doing so requires an explicit training cutover and metrics.
- No counterfeit Nash equilibrium or game-theoretic validity claim is attached to synthetic opponent behavior.
- This first smoke includes three fully traced game examples, not nine levels for every one of the 231 registered games. The rest require specific game-dependent executable extraction oracles before becoming training examples.
- Some executable *legacy* transformation labels represent valid text-rendering operations rather than standalone scalar arithmetic. Their reference execution remains in the original legacy generator.
