# NanoJev Game Math v3 — Executable T08↔T00 Edge Programs

## Intent and proof boundary

Each adjacent downward tier transition is now a **source-authored executable
program**, stored as inspectable pseudocode and a versioned opcode in the same
source-generated SQLite database. The program parses its own source prompt,
executes the mathematical registry, and emits its target tier. `execute_down`
does NOT accept a gold answer, frozen case record, or hidden scenario witness.

Reconstruction in the other direction is not a mathematical inverse: the input
`(X,Y,OP)` can arise from many different stories. Every upward transition
therefore uses a **sealed scenario witness**, *and must recompile through the
corresponding downward program* to prove consistency.

Proof scope: the versioned, constrained prompt grammar across the three current
example games, NOT arbitrary natural-language understanding, broad auction
optimality, or a trained neural math head. Some tiers intentionally re-express
facts instead of introducing new arithmetic. Any mathematical substeps hidden
inside one tier remain separately recorded in `ladder_transition_math_steps`.

## Programs

| Downward edge | Executed program | Operation and evidence |
|---|---|---|
| T08→T07 | `EXTRACT_OBSERVATIONS` | Parse public story; evaluate frozen game; structured rules |
| T07→T06 | `RESOLVE_RULE_SELECTION` | Parse rule table; select opponent-conditioned rules |
| T06→T05 | `COMPILE_OPERAND_TAGS` | Recompute full graph; bind derived operands to tagged expressions |
| T05→T04 | `BIND_TAGGED_OPERANDS` | Convert named expressions to mathematical expressions |
| T04→T03 | `EVALUATE_RIGHT_EXPRESSION` | Run X/Y-tag AST; retain trace of every mathematical node |
| T03→T02 | `EVALUATE_LEFT_EXPRESSION` | Evaluate the first tagged expression |
| T02→T01 | `INTRODUCE_REGISTERS` | Rebind unregistered numeric operands |
| T01→T00 | `EXPLICIT_OPERATION` | Compile operator language to the registered OP identifier |

### Auction: T04→T03 concrete mathematical substeps

```text
(125, LOW_INTELLIGENCE, HIGH_NEED, LOWER_BOUND)
  LOW_INTELLIGENCE(125)                  -> [62.5, 187.5]
  HIGH_NEED(62.5)                       -> 62.5
  HIGH_NEED(187.5)                      -> 187.5
  LOWER_BOUND([62.5,187.5])            -> 62.5
```

`LOWER_BOUND` is now a source-defined operator (`interval -> scalar`) with
independent gold-vector verification. A valid synthetic auction scenario also
executes the full `OPTIMAL_BID_UNIFORM` and verifies its MIDPOINT reduction.

## New database tables

- `ladder_transition_programs`: program IDs, public pseudocode, opcode,
  implementation checksum, source and target tiers.
- `ladder_transition_executions`: all **downward source-only** and **upward
  witness-backed** executions with independent checksums.
- `ladder_transition_math_steps`: individual recorded mathematical/semantic
  operations with their inputs, outputs, and place in the execution sequence.

The smoke *replays all stored programs from source*, checks every intermediate
output, and rejects mismatched source definitions, corrupted prompts, rows, or
operator traces. It only emits PASS when every case completes all transitions.

## Commands

Apply this incremental source-only ZIP after v2, rooted at `main_computer_test/`.
From repository root:

```powershell
$py = 'C:\Users\subsi\NanoJev\.venv\Scripts\python.exe'

& $py -m unittest `
    tests.test_nanojev_game_ladder_edge_programs `
    tests.test_nanojev_game_ladder_bidirectional_proof `
    tests.test_nanojev_game_math_smoke `
    tests.test_nanojev_game_transformation_library -v

& $py -m tools.nanojev_game_math_smoke --generate --verify-all --report

& $py -m tools.nanojev_game_ladder_edge_programs `
    --database runtime/game-math-source-smoke-v3/game_transformations.sqlite3 `
    --case first_price_captain_uncertainty:case-00
```

All database files are generated by the smoke. It never changes the trained head,
its checkpoint, active task-bank records, or the prior v1/v2 output directories.
The next growth axis is to introduce new game-specific AST extraction programs
and operator domain proofs, **not** to train on these 72 proof-only scenarios.
