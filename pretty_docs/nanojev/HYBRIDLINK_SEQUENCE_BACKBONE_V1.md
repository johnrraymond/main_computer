# NanoJev HybridLink Sequence Backbone v1

## Purpose

This is a **new, independent** numerical adaptation of the *Hybrid Reasoning
Agents* hidden-to-input recurrence, not a continuation of the v4 sidecar and not
an upstream HybridAgent port. The official paper is
<https://arxiv.org/html/2610.18861> and code is
<https://github.com/togethercomputer/HybridAgent>.

## Explicit architectural contract

Given a fixed initial sequence of **two numerical embeddings** (the visible
count/payoff features projected to hidden width, and the original Gaussian
network's pretrained late activation projected to hidden width), use **one
shared trainable causal Transformer** `F` and residual `HybridLink R`:

```
context = numerical_seed_tokens(features)   # length 2
for t in range(4):
    state = F(context)[:, -1, :]             # shared F weights
    thought_t = R(state)                     # hidden -> input embedding
    context = cat(context, thought_t)        # length grows from 2 to 6
answer = answer_head(F(context)[:, -1, :])   # only final head predicts X/Y
```

There are no X/Y predictions, Gaussian bank codes, oracle products, or
teacher tokens in the **inference feedback loop**. All older source files
and checkpoint weights stay unchanged. The original pretrained Gaussian MLP
supplies the second input token; it is *frozen*, while the new causal
sequence backbone is trained. This differs from the paper, whose **original
pretrained Transformer backbone itself** is jointly fine-tuned. The new
sequence backbone is NanoJev's trainable analogue of that sequence-processing
component, **not** a claim that the old Gaussian MLP has become a Transformer.

The output head is a separate **direct** normalized X/Y readout. The original
Gaussian bank decoding is neither required nor modified. It can be revisited
later as an alternative answer interface; it does not drive latent feedback.

## Three training stages

1. **Format activation** (`--format-steps`): fit the new sequence backbone,
   numerical seed interface and typed teacher-product embeddings using only
   visible four count×payoff partial products. Supervise the final X/Y result
   and a per-stage numerical product readout. HybridLink remains frozen.
2. **HybridLink alignment** (`--align-steps`): freeze the sequence backbone,
   input encoders and answer head. Use teacher-forced contexts and train the
   residual link using cosine+MSE regression onto **input-space embeddings**
   generated by the activated typed-product encoder.
3. **Two-pass self-conditioned joint training** (`--joint-steps`): first run
   a teacher-conditioned pass to produce predicted latent inputs. Then feed
   those actual generated embeddings into the **same trainable sequence
   backbone** on the second pass. Jointly train backbone and link with final
   X/Y loss plus latent-position alignment. The first-pass embeddings are
   detached to simulate cached generated contexts; a separately labeled
   numerical adaptation adds `--autonomy-weight` free-running inference loss
   (default 0.25), which is **not** part of the paper's original objective.

The teacher products are training-only structure derived from the permitted
six numerical operands; they do not appear as oracle inputs at inference.
This is a fixed-depth numerical HybridSFT analogue: it does **not** implement
text-token mode switching, tool use, dynamic entry/exit, or HybridRL.

## Controlled experiment

`recurrent` generates four thoughts by reading the expanded context through
`F` after **each** appended thought. `static` has the same trainable module
inventory, same initialization and training update count, but proposes its
four thoughts from the original seed hidden state and step embeddings, with
only one full backbone pass at the end. Both see the same numerical features,
training splits and X/Y targets. This is a no-recursive-read control, not an
identical-FLOP comparison (the recurrent model performs more backbone work).

Depths 0/1/2/4, zeroed thoughts, repeated-first thoughts and reversed thoughts
are DEV ablations of each selected checkpoint. Depth-1 and depth-2 ablations
of a depth-4-trained model are **not** independently trained depth controls.
The feedback `PASS` gate requires **at least 2 absolute percentage points on
all eight DEV tiers** relative to the original Gaussian reference, the separately trained static
model, zeroed thoughts, and repeated-first thoughts. Otherwise `NOT_ESTABLISHED`. TEST is
untouched by default; `--final-test` is opt-in and included in immutable run
identity. This experiment may fail to improve the reference Gaussian's ~61%
score; architecture correctness is not evidence of numerical success.

## Install and run (Windows Python)

Install the ZIP rooted under `main_computer_test/`:

```
python new_patch.py nanojev_hybridlink_sequence_backbone_v1_patch.zip --dry-run
python new_patch.py nanojev_hybridlink_sequence_backbone_v1_patch.zip
```

Then run the default head-to-head experiment in a **new empty** directory:

```
python -m tools.nanojev_hawk_dove_hybridlink_sequence --reference-checkpoint "C:\Users\subsi\NanoJev\runs\hawk_dove_gaussian_2000_blind_matrix_v1_replay-1\best.pt" --output "C:\Users\subsi\NanoJev\runs\hawk_dove_hybridlink_sequence_v1" --device cuda --format-steps 600 --align-steps 400 --joint-steps 1400 --probe-every 200 --batch-size 128
```

For pause/restart add `--stop-after 800` to the initial command, then repeat
without `--stop-after` and add `--resume`. The script refuses any change in
checkpoint hash, source split identity or training configuration on resume.
For quick diagnostic use `--format-steps 20 --align-steps 20 --joint-steps 40
--probe-every 20` with a new output directory; a quick run is **not** expected
to meet accuracy gates.

Outputs: `config.json`, `recurrent/{latest.pt,best.pt,done.json}` and
`static/{latest.pt,best.pt,done.json}`, then `report.json`. Stage-specific
DEV progress prints as `HYBRIDLINK_TRAIN`, and final causality decision as
`HYBRIDLINK_FEEDBACK`.

## Source integrity / limitations

The original Gaussian source is loaded using `weights_only=True`, validated
against its schema, matrix hashes and numeric domain, and SHA-checked again
after the run. TRAIN drives optimization and DEV selects checkpoints. No
source- or output-directory mutation outside the dedicated new run directory.
The default study evaluates TEST **zero** times. Exact-zero targets are still
judged under the strict 5% relative-error metric.

Unlike a pretrained language Transformer, this numerical sequence backbone
begins untrained and needs format activation. This substantially changes the
training difficulty and limits direct performance claims about HybridAgent.
The auxiliary teacher-product representation is a supervised numerical
adaptation, not a proven interpretation of the paper's latent tokens.
