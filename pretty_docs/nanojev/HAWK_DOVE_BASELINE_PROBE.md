# Hawk–Dove Ladder Baseline Probe — read-only

## Purpose

Measure the **current** `nanojev_altreg_attention_curriculum_mix_v4.py` head, before inserting new Hawk–Dove examples into the task database. This is an evaluation utility, not a trainer cutover.

It imports the repository's actual ten captain jackets, three shared scenarios, categorical state/rubric oracle, and eleven-level raw-story-to-LogBar ladder. It loads `latest.pt` (or `best.pt`), its checkpoint-identified parent, the trained X/Y decoder and 14-way operation head, and the same frozen Qwen capture path used in the trainer. It does **not** load optimizer state or write checkpoint, task database, training schedule, or model weights. It writes no files unless you explicitly provide `--report`.

The checkpoint is on your workstation, not bundled with this patch; therefore local GPU inference is required for actual scores. Contract tests do not require the model or checkpoint.

## Install

Unzip the patch under your checkout so its `main_computer_test/tools/` and `main_computer_test/tests/` paths land at `C:\Users\subsi\main_computer\tools\` and `...\tests\` respectively. Run commands from the repository root.

## Fast probe (a diagnostic, not an accuracy certification)

```powershell
$py = 'C:\Users\subsi\NanoJev\.venv\Scripts\python.exe'
& $py -m tools.nanojev_hawk_dove_baseline_probe `
  --checkpoint latest --device cuda `
  --captains c01,c03,c05 --scenarios s01 `
  --states-per-scenario 2 --batch-size 4 `
  --report .\runtime\hawk-dove-quick-probe.json
```

This probes six **distinct** captain–scenario–state cases (each through eleven rungs and the two exact legacy formats), hence the tool correctly withholds any generalization qualification (`--min-cases 30` by default). Use it to check actual checkpoint wiring, token compatibility, and prediction behavior.

## Baseline for choosing a starting rung

```powershell
& $py -m tools.nanojev_hawk_dove_baseline_probe `
  --checkpoint latest --device cuda --batch-size 8 `
  --captains all --scenarios all --states-per-scenario 2 `
  --focus both `
  --report .\runtime\hawk-dove-baseline-probe.json
```

This creates 60 canonical cases (10 jackets × 3 shared scenarios × 2 categorical states). Both X/Y-removal orientations are evaluated, with duplicate texts deduplicated. Each row reports joint X/Y within 5% and 1%, separate operand accuracy, operation accuracy, sign of X-Y decision, and the accuracy when the decoder's operation-ID input is neutralized. The same rubric and targets are used across all eleven ladder levels. The two additional controls are the trainer's **exact** `registered_logbar` and `plain_expression` prompts for the same X/Y values, to detect a formatting jump at L00.

## Rung qualification / interpretation

- `L00` easiest numeric scaffolding; `L10` full English jacket/situation/opponent/question.
- `highest_contiguous_pass` is the highest level in a prefix that meets the configured thresholds; a later rung performing better on its own does not excuse a failed earlier rung.
- By default a rung requires **30 independent captain–scenario–state cases** (not 30 copies generated by two orientations), no overlength inputs, 80% joint X/Y within 5%, and 80% operation accuracy. These are *provisional screening thresholds*, not a demonstration of generalized captain competence.
- `neutral joint5%` measures the same language representations with the decoder's operation-ID side-channel masked. Large differences reveal reliance on the operation shortcut.
- `decision_accuracy` checks whether the **predicted** sign(X−Y) agrees with the synthetic teacher. It is not evidence that the synthetic teacher's choice is strategically optimal.
- All smoke examples have the same `SUB` operation, so success does **not** test recognition of unseen mathematical operations.
- Many longer jackets may exceed the checkpoint's `max_prompt_tokens` (the example checkpoint was 256). They are reported as `token_limit`, **not truncated or incorrectly scored as failures**. `--max-tokens 384` or `512` can separately explore longer inputs, but results are explicitly flagged as outside the trained prompt-length setting.
- The `--answer-suffix` ablation appends `Answer:` to prompts lacking it. This isolates effects of the original training prompt convention. Run it as a **separate** report.
- Individual failures and a complete deterministic case manifest are included in the optional JSON report. A SHA256 of the checkpoint and ladder generator identifies the evaluated implementation.
- If the current trainer is using the same CUDA device simultaneously, run the probe when that workload is not occupying the GPU to avoid memory contention. No training state needs resetting.

## Tests

```powershell
& $py -m unittest tests.test_nanojev_hawk_dove_baseline_probe -v
```

No task bank is populated. No new training run or checkpoint fork is created. Once the local probe results show the actual cliff, choose the first *not-yet-reliable* representation as the frontier and retain replay of already mastered representations.
