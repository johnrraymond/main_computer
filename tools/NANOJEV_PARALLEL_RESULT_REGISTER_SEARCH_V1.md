# Parallel RESULT Register Search v1 — additive experiment

## Objective

Use **one forward capture of frozen Qwen3-0.6B per fresh minibatch** to train seven independent RESULT readouts on identical examples. Compare direct numerical reconstructions to the frozen X/Y + executable arithmetic reference. Train no Qwen weights; overwrite no earlier result lineage; authorize **no** deployed RESULT replacement. Requires existing `register_stability_v3` activation benchmark and the existing **buffered 38-head decoder** source checkpoint.

**Important compatibility detail:** The current adapter deliberately accepts `nanojev.register-online-hierarchy-buffered.v1` checkpoints (for example `register_online_hierarchy_buffered_v1/best.pt`). It does **not** deserialize the newer `register_operation_result_cutover_v1_2/latest.pt`, which has a different schema and is not contained in the available source snapshot. The R0 reference is therefore the buffered 38-head operand decoder **plus a jointly trained, independently optimized 20-class operation probe**, not a direct reproduction of v1.2's published 19.57% numeric RESULT baseline. Compare the new numeric scores against R0 within the same run, not against a v1.2 score on a different data selection. Preserve v1.2 untouched.

## Registers and supervision

| Register | Numerical output objective | Decode |
|---|---|---|
| R0/source | Frozen operand X/Y decoder + operation probe | Execute discrete operation in Python |
| R1/continuous | Signed asinh RESULT, smooth L1 | Inverse asinh + round |
| R2/scientific | Decimal exponent CE + log10 mantissa residual | Sign × 10^(exponent + fraction) |
| R3/digits | Left-aligned decimal digit classes plus PAD | Reconstruct integer from leading digits |
| R4/place | Ten-class decimal digit per place + digit-count class | Sum digit × 10^place |
| R5/ordinal | 14 cumulative decimal thresholds + continuous within-decade coordinate | Longest threshold prefix, then fractional log10 |
| R6/bits | 48 independent binary bits | Exact bitwise integer recombination |
| R7/residual | Asinh correction to frozen source RESULT | Inverse asinh after additive correction |

All readouts use the same width for two hidden layers, and each has a **separate optimizer and independent checkpoint selection**. R1/R7 are smooth continuous regression targets; R2/R3/R4/R5/R6 use discrete or mixed targets. Each readout includes auxiliary sign, zero, and Boolean logits. All 20 known operation templates are learned by a shared independent linear probe on frozen activations. The operation probe prediction (not its gold label) is passed to all seven heads; R0 also executes the predicted operation. The training target is computed from the training-example X, Y and labeled operation; these values never enter inference features. R3/R4/R6 supervision uses original `float64` exact integer-valued labels up to 16 trillion: it **does not** route high-precision digit labels through `float32`.

The original Qwen layer/suffix capture rule is reused unchanged: four suffix tokens from layers 16 and 28, producing 8192 features. Existing benchmark capture files are reused for validation; Qwen is not rerun for evaluation. New examples are generated by `FreshPairs` and exclude **every pair present anywhere in the fixed benchmark**. Replay samples (features, frozen source operands, and targets) are shared across heads, with separate optimizers. A 2-update replay setting means one fresh Qwen capture drives 14 small-head updates + 2 operation-probe updates.

## Run: new lineage only

```powershell
$common = @(
  '--v3-root', "$env:USERPROFILE\NanoJev\runs\register_stability_v3",
  '--source-checkpoint', "$env:USERPROFILE\NanoJev\runs\register_online_hierarchy_buffered_v1\best.pt",
  '--results-root', "$env:USERPROFILE\NanoJev\runs\parallel_result_register_search_v1",
  '--width', '128',
  '--batch-size', '16',
  '--replay-capacity', '4096',
  '--replay-batch', '32',
  '--replay-updates', '2',
  '--val-examples', '512',
  '--eval-every', '100',
  '--checkpoint-every', '100',
  '--report-every', '50',
  '--lr', '0.0003',
  '--device', 'cuda',
  '--dtype', 'float16',
  '--threads', '2'
)

# Optional shorter CUDA pilot before full run:
& $py .\tools\nanojev_parallel_result_register_search.py @common --steps 100

# Resume the same lineage (same configuration; increase steps):
& $py .\tools\nanojev_parallel_result_register_search.py @common --steps 3000 --resume

# Read frozen aligned latest checkpoints on val/test/control, without Qwen:
& $py .\tools\nanojev_parallel_result_register_search.py @common --eval-only
```

Starting from scratch, replace the 100-step pilot with `--steps 3000`. If the result root already contains `latest.pt`, the default training invocation refuses to overwrite it; use `--resume`. The benchmark root, source checkpoint and backbone revision must match exactly. `--eval-only` deliberately compares the **aligned latest step** for every readout and operation probe, not a mixture of individually best readout checkpoints from incompatible training steps. Individual `best.pt` and `latest.pt` files still exist for every readout.

## Output files

```
parallel_result_register_search_v1/
    run_config.json
    latest.pt                        # all heads, all optimizers, stream, replay, RNG
    validation-step-000100.json      # all metrics, cases, overlap, oracle upper bound
    correctness-step-000100.npy      # rows x 8 boolean correctness matrix
    continuous/{best.pt,latest.pt}
    scientific/{best.pt,latest.pt}
    digits/{best.pt,latest.pt}
    place/{best.pt,latest.pt}
    ordinal/{best.pt,latest.pt}
    bits/{best.pt,latest.pt}
    residual/{best.pt,latest.pt}
```

Each validation reports operation accuracy, original source X/Y joint accuracy, RESULT scores separately for Boolean and numerical rows, exact RESULT, 1/2/5/10/20/50% numerical accuracy, numeric signed-asinh and relative error, per-family accuracy, rescued original-source failures, damaged original-source successes, a head-by-head correctness-overlap matrix, and **oracle candidate-pool accuracy**. Oracle pooling uses answers to choose among candidates **only for analysis**; it is not a deployable selector. No ensemble is authorized, and no training truth is passed into inference.

**Caution on held-out operations:** The benchmark `control` split includes four operation templates absent from the 20-class training catalog. Scores there demonstrate extrapolation failures; they do not establish an implementation of those unseen operations in the trained operation head. The primary comparison is the same held-out validation/test data restricted to supported operations.

## Safety and scope

- The script verifies the source-buffered-checkpoint schema and exact Qwen model identity, fingerprints source checkpoint bytes and puts the fingerprint in the run configuration; it never writes into the source checkpoint or benchmark tree.
- Resumption verifies exact configuration and restores each optimizer, replay sample RNG, fresh-pair stream, torch RNG and CUDA RNG.
- Full-catalog arithmetic execution is used as a training label generator and for evaluating frozen predictions; the source operation is **predicted** rather than read from labels at inference time.
- This experiment does not implement a production RESULT register selector and makes no performance claim until trained on the user's CUDA hardware.

## Tests run when packaged

`--self-test`: verifies seven independent gradients, target encodings, loss finiteness, exact arithmetic, and replay/checkpoint mechanics on CPU. Pytest suite: unit tests plus complete **mocked** training/resume/eval-only across all seven readouts using a real saved *fixture* for the 38-head source, but artificial Qwen features. No CUDA training, 23,552-prompt capture, or Qwen download is performed by these tests.
