# NanoJev three independent alternating-register math experiments (v1)

## Scope and backbone identities

This patch creates **three standalone training scripts**, not a multi-backbone head, and **three standalone test modules**:

| Arm | Independent program | Frozen HF model | Default independent output |
|---|---|---|---|
| Qwen | `tools/nanojev_altreg_independent_math_qwen.py` | `Qwen/Qwen3-0.6B` (existing pinned revision) | `%USERPROFILE%\NanoJev\runs\independent_altreg_math_qwen_v1` |
| Pythia | `tools/nanojev_altreg_independent_math_pythia.py` | `EleutherAI/pythia-70m` | `%USERPROFILE%\NanoJev\runs\independent_altreg_math_pythia_v1` |
| TinyStories | `tools/nanojev_altreg_independent_math_tinystories.py` | `roneneldan/TinyStories-33M` | `%USERPROFILE%\NanoJev\runs\independent_altreg_math_tinystories_v1` |

**Independence:** Every script contains its own trainer, math-head classes, optimizers, RNG stream, checkpoint reader/writer, validation cache, and selection logic. No script imports any of the other two scripts, loads another arm's checkpoint, or writes to another arm's results. They use only existing project `nanojev_numerate_spine_cassette_smoke` for frozen model loading and `nanojev_register_stability_v3_generate` for immutable task definitions. These shared *input definitions* are not shared experiment state.

## Experimental contract

* All three heads are randomly initialized with the same seed and trained from step zero. **Do not attach a Qwen v3.7/v3.9 checkpoint to Pythia or TinyStories.** This is a matched fresh-start experiment, **not** a byte-identical reimplementation of the complex v3.7 hierarchy / RESULT controller. The existing v3.7/v3.9 results remain untouched.
* Every backbone captures 4 final prompt tokens from its own middle and last hidden-state layers. These are flattened and fed to an otherwise identical trainable mathematical head (input width adapts automatically to each backbone's hidden size). The backbone is frozen and checked for zero trainable parameters.
* X and Y represent the same A and B, irrespective of register-line order. The instruction and all regression targets stay unchanged. The original and reversed prompt variants are paired on identical validation and test examples.
* On the 16/20 X/Y update ticks, consecutive samples alternate original and reversed prompt order deterministically. The 3/20 RESULT ticks and 1/20 FINAL tick retain original-order prompts; original RESULT/FINAL are not exposed to the new presentation distribution.
* Training targets: known X/Y normalized signed-asinh coordinates; RESULT exact mathematical oracle, normalized signed-asinh; FINAL learned residual correction. The supervision distribution is 80%/15%/5%. Optimizers and checkpoints are private per arm. This fresh-start architecture is intentionally simpler than the prior NanoJev v3.7 expert ensemble; therefore its absolute errors must not be compared as if they were the same model architecture.
* Validation reports **both** signed-asinh MSE and relative MSE under `original`, `reversed`, and deterministic *label-aligned average*, with precise field names. Very high but finite initial errors are allowed. Gradient and loss non-finiteness are rejected, gradient norms clipped to 1.0.
* Split assignment is based on register-pair groups generated by the original v3 seeded plan. Fresh training pairs cannot match held-out validation, test, or control pair groups; all three scripts generate the same example partitions and stream sequence.
* Champion uses the mean of original + reversed X/Y signed-asinh squared errors, not RESULT, FINAL or one favored prompt ordering.

## Installation

Extract this patch into the established `main_computer_test/` patch workflow, placing the `tools/` and `tests/` files under `C:\Users\subsi\main_computer`.

## Offline self-tests (no model downloads)

```powershell
$py = 'C:\Users\subsi\NanoJev\.venv\Scripts\python.exe'
& $py .\tools\nanojev_altreg_independent_math_qwen.py --self-test
& $py .\tools\nanojev_altreg_independent_math_pythia.py --self-test
& $py .\tools\nanojev_altreg_independent_math_tinystories.py --self-test
& $py -m pytest -q .\tests\test_nanojev_altreg_independent_math_qwen.py
& $py -m pytest -q .\tests\test_nanojev_altreg_independent_math_pythia.py
& $py -m pytest -q .\tests\test_nanojev_altreg_independent_math_tinystories.py
```

## Independent first training runs (GPU)

**Run each command independently, preferably sequentially to avoid three frozen backbones competing for the same GPU.** The `--allow-model-download` flag only allows Hugging Face to populate missing local model weights; omit it if they are already cached.

```powershell
& $py .\tools\nanojev_altreg_independent_math_qwen.py `
  --device cuda --dtype float16 --steps 200 --eval-every 100 --report-every 50 `
  --val-examples 128 --test-examples 128 --allow-model-download

& $py .\tools\nanojev_altreg_independent_math_pythia.py `
  --device cuda --dtype float16 --steps 200 --eval-every 100 --report-every 50 `
  --val-examples 128 --test-examples 128 --allow-model-download

& $py .\tools\nanojev_altreg_independent_math_tinystories.py `
  --device cuda --dtype float16 --steps 200 --eval-every 100 --report-every 50 `
  --val-examples 128 --test-examples 128 --allow-model-download
```

To continue **one arm only**, use the same script and its same validation/test sample counts:

```powershell
& $py .\tools\nanojev_altreg_independent_math_pythia.py `
  --device cuda --dtype float16 --resume --additional-steps 5000 `
  --eval-every 100 --report-every 50 --val-examples 128 --test-examples 128
```

Replace the filename with the Qwen or TinyStories script for those independent resumptions. The destination is the script's private default; you can supply another **unique**, initially empty `--results-root` before the first run. For resume, use that identical destination.

## What to inspect

Each arm's output directory alone contains:

* `baseline.json`: original, reversed and averaged X/Y, RESULT, FINAL before the first update.
* `validation-cache.pt`: same held-out problems captured from that one frozen backbone; original + reversed captures.
* `validation-step-00000100.json` and subsequent: paired accuracy including X/Y + RESULT + FINAL and the three inference modes.
* `latest.pt` / `best.pt`: one arm's complete **separate** math-head weights, optimizers, RNG stream, phase counters, dataset and backbone identities.
* `test-last.json`: held-out test results from that one arm's last checkpoint.

Use `--eval-only --val-examples 128 --test-examples 128` with the specific arm's script for independent latest-checkpoint evaluation, without loading its frozen backbone.
